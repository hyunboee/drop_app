## 1. 개요

### 1.1 문제
도메인 정의서 1.1(P1~P3) 참조. 요약하면 오프라인 방문의 진정성 부족, 공간에 고정된 AR 콘텐츠 플랫폼 부재, 위치 콘텐츠의 C2C 수익 구조 부재다.

### 1.2 목표
- **비즈니스 목표:** 현실 공간을 디지털 부동산으로 바꾸는 C2C 생태계를 만든다.
- **MVP 목표(2일):** "현장에서 AR로 캡슐을 고정하고(드롭), 미디어를 S3에 올리고, PostgreSQL에 저장한 뒤, 다른 사용자가 현장에서 AR로 열람한다"는 핵심 흐름 하나를 실제 스마트폰에서 끝까지 검증한다.

### 1.3 성공 지표 (KPI)

| 구분 | 지표 | 목표 |
|---|---|---|
| MVP 검증 | 실기기(iOS Safari, Android Chrome)에서 드롭→열람 전 흐름 성공 | 두 플랫폼 모두 성공 |
| MVP 검증 | 드롭한 캡슐이 같은 장소 재방문 시 AR 뷰에 표시되는 비율 | 10회 시도 중 8회 이상 |
| 비용 | 같은 뷰어가 같은 미디어를 다시 열람할 때 S3/CDN 재다운로드 비율 | 0%에 가깝게 (NFR-05) |
| 후속 단계 | 주간 드롭 수, 캡슐당 평균 열람 수, 드롭 사용자 중 재드롭 비율 | 출시 후 기준선 측정 뒤 설정 |

## 4. 기능 요구사항

우선순위: P0 = MVP 필수, P1 = MVP 여유 시, P2 = 후속 단계

| ID | 요구사항 | 우선순위 | 수용 기준 |
|---|---|---|---|
| FR-01 | 회원가입·로그인 | P0 | 이메일+비밀번호(규칙 M-10)로 가입·로그인할 수 있다. 가입 시 필수 동의 3개(이용약관·개인정보 처리, 위치정보 이용(PRV-07), 만 14세 이상 자기 확인)를 모두 체크해야 한다. 로그아웃은 FAB 메뉴에서 한다(7장). 비로그인 상태에서는 AR 뷰를 포함한 모든 API가 401을 반환한다(BR-01). 비밀번호는 Node `crypto.scrypt` 해시로 저장한다. 이메일 중복 가입은 409를 반환한다. 로그인 실패는 계정 존재 여부를 드러내지 않는 같은 메시지로 401을 반환하고, 같은 이메일로 연속 실패가 M-05를 넘으면 잠그고 429를 반환한다. 세션 토큰은 `HttpOnly; Secure; SameSite=Strict` 쿠키로만 전달한다(같은 출처 서빙 전제, 6장). 세션은 M-04 동안 유효하고, 로그아웃하면 DB에서 세션을 지운다 |
| FR-02 | 권한 획득 | P0 | 앱에 들어올 때마다 "시작" 화면을 거치고, "시작" 탭으로 카메라·위치·방향 센서 권한을 요청한다(iOS 방향 센서는 사용자 탭이 필요하고, 이미 허용했으면 바로 통과한다). 세 권한 모두 필수이며, 하나라도 거부하면 AR 뷰 대신 권한 안내 화면을 보여 주고 재시도 버튼을 제공한다 (위치형 AR은 방향 없이 프레임을 배치할 수 없다). 브라우저가 권한을 차단해 다시 묻지 않으면 "브라우저 설정에서 권한을 허용한 뒤 재시도" 안내를 함께 보여 준다 |
| FR-03 | 캡슐 드롭(앵커링) | P0 | FAB → "드롭" 선택 시 현재 GPS 좌표, 정확도(accuracy), 기기 방향(heading)을 캡처해 앵커로 저장한다. GPS 정확도가 재측정 기준(PRM-03)보다 나쁘면 드롭을 막고 재측정을 안내한다(서버는 422) |
| FR-04 | 미디어 업로드 | P0 | 사진 1장을 고른다(`<input type="file" accept="image/*">`, 웹에서는 촬영 옵션 노출을 허용, Q-10). 브라우저가 선택한 사진을 Canvas로 JPEG 재인코딩(긴 변 M-13)해 원본으로 쓴다(HEIC·WebP 입력 호환, EXIF 위치정보 제거). 서버가 발급한 S3 Presigned URL로 브라우저가 직접 업로드한다. 이미지 여부와 최대 크기(M-06)를 사진 선택 시 브라우저에서 먼저 검사하고, 서버에서 다시 검증한다. 업로드가 네트워크 오류로 실패하면 Presigned URL을 다시 받아 같은 사진으로 재시도할 수 있다. 브라우저가 Canvas로 썸네일(M-07, JPEG)을 만들어 원본과 함께 올린다(새 라이브러리 없음). S3 키는 서버가 발급한 UUID(`mediaId`)로 정하며(원본 `media/{mediaId}.jpg`, 썸네일 `media/{mediaId}.thumb.jpg`), Presigned PUT에 `If-None-Match: *`를 서명해 같은 키에 두 번째 업로드를 막는다(412). 업로드 객체에는 `status=pending` 태그를 붙이고, S3 수명 주기 규칙이 태그가 남은 객체를 M-08 뒤 지운다 |
| FR-05 | 영상 업로드 | P2 | 갤러리 영상(최대 30초, 50MB)을 FR-04와 같은 방식으로 업로드하고, Rekognition 비동기 검열 결과를 폴링으로 확인한다 (Q-09) |
| FR-06 | AI 사전 검열 | P0 | 업로드가 끝나면 클라이언트가 앵커·제목·미디어 키를 한 번에 게시 요청한다. 서버는 원본과 썸네일을 Rekognition `DetectModerationLabels`(동기, 제한 시간 M-09, 기준 M-14)로 검사한다. 둘 다 통과하면 S3 태그를 지우고 캡슐 행을 Active로 만든다. 하나라도 거부되면 캡슐 행을 만들지 않고 S3 객체를 지운 뒤 422로 사유를 알린다. Rekognition이 실패하거나 시간을 넘기면 캡슐 행을 만들지 않고 503과 "다시 시도"를 안내한다(업로드한 객체는 그대로 두고 재요청에 쓴다). 검열을 통과하지 않은 캡슐은 어떤 조회 API에도 나오지 않는다(BR-33) |
| FR-07 | 등급·게시 | P0 | 제목은 필수이며 길이는 M-11이다(서버에서도 검증). MVP는 브론즈만 허용하고 결제 없이 게시한다(Q-04). 서버는 브론즈 외 등급 요청을 400으로 거부한다. 검열 통과 시 Active가 되고 `expires_at = published_at + 브론즈 유지 기간`(도메인 정의서 5.1, PRM-06: 720시간)으로 계산한다. 게시 응답에 `expires_at`을 담아 완료 화면에 "○월 ○일까지 보여요"로 안내한다 |
| FR-08 | 주변 캡슐 조회 | P0 | 현재 위치 기준 조회 반경(M-01) 안의 Active·미만료 캡슐 목록(제목, 좌표, 썸네일 경로 `/api/media/:mediaId/thumb`)을 반환한다. 만료 캡슐은 제외한다(BR-11) |
| FR-09 | AR 표시 | P0 | 조회된 캡슐을 AR.js 위치 기반 엔티티(3D 프레임)로 카메라 뷰에 띄운다. 위치 갱신 시 목록을 다시 받는다(최소 간격 M-02) |
| FR-10 | 캡슐 열람 | P0 | 프레임을 터치하면 서버가 뷰어 좌표와 캡슐 좌표의 거리 d를 계산해 도메인 정의서 5.4의 판정식 `d − min(accuracy, 보정 상한 PRM-03) ≤ 열람 반경 PRM-01`을 만족할 때만 원본 미디어 경로(`/api/media/:mediaId`)를 반환한다(Q-03). 이 경로는 세션 쿠키가 필요하고, 그 뷰어의 해당 캡슐 열람 기록이 있거나 소유자일 때만 200, 아니면 403, 만료·삭제 캡슐이면 404를 반환한다(NFR-08). Express가 EC2 인스턴스 역할로 S3 GetObject해 스트리밍하며 브라우저에 S3 URL을 주지 않는다. accuracy가 재측정 기준(PRM-03)보다 나쁘면 판정하지 않고 422로 재측정을 안내한다. MVP는 별도 증명을 발급하지 않고 열람 요청에서 바로 판정한다(평면 일치·이동 속도·무결성·유효 시간은 생략, Q-11). 반경 밖이면 남은 거리를 안내한다(BR-27). 만료·삭제되어 더 볼 수 없는 캡슐이면 404를 반환하고, 클라이언트는 "더 이상 볼 수 없는 캡슐이에요"를 안내한 뒤 주변 목록을 다시 받는다. 열람 기록(ViewRecord)을 저장한다. MVP는 증명을 발급하지 않으므로 presence_proof_id는 NULL로 두고, 대신 뷰어 좌표·accuracy·IP 해시(서버 비밀값으로 HMAC-SHA256, 원문 저장 금지, PRV-04)를 함께 저장한다(INV-06, Q-11) |
| FR-11 | 내 캡슐 삭제 | P1 | 소유자가 자기 캡슐 프레임을 탭하면 열람 화면에 "삭제" 버튼이 보인다(별도 화면 없음). 누르면 "삭제하면 되돌릴 수 없어요" 확인(브라우저 기본 `confirm`)을 거친다. 소유자만 삭제할 수 있고, 삭제 즉시 조회에서 제외된다. 원본·썸네일 S3 객체도 지운다(키를 공유하지 않음) |
| FR-12 | 결제·유료 체크포인트·보상·정산·프라이빗·신고·제재 | P2 | 도메인 정의서 BR-07~09, BR-12~25, BR-28~40을 따른다. 네이티브 앱 전환(Q-01) 시 별도 PRD로 상세화한다 |

## 7. UX 원칙

- **풀스크린 AR 카메라 뷰가 기본 화면이다.** 로그인 직후 바로 카메라 뷰로 들어간다. 별도 홈 화면이나 탭은 MVP에 두지 않는다.
- **화면 하단 중앙의 플로팅 액션 버튼(FAB) 하나**로 핵심 행동을 한다. 탭하면 "주변 스캔(새로고침)"과 "여기에 드롭" 두 가지를 고른다. 메뉴 하단에는 작은 "로그아웃" 텍스트 버튼만 둔다(별도 메뉴 화면 없음). FAB는 어느 상태에서든 항상 보인다.
- 드롭 흐름은 FAB → 사진 선택 → 제목 입력 → 업로드·검열 진행 표시 → 완료, 최대 4단계 바텀시트로 끝낸다. MVP는 브론즈 고정이라 등급 입력 단계가 없다(FR-07). 업로드·검열 진행 중에는 시트를 닫을 수 없다. 완료하면 주변 목록을 즉시 다시 받아 새 캡슐이 바로 보이게 한다.
- 열람 가능한 캡슐(반경 안)과 불가능한 캡슐(반경 밖)을 프레임 색이나 투명도로 구분하고, 반경 밖 캡슐에는 남은 거리를 표시한다. 남은 거리는 서버 판정식과 같은 기준인 `max(0, d − min(accuracy, 보정 상한 PRM-03) − 열람 반경 PRM-01)`로 클라이언트가 계산한다. 반경 밖 프레임을 탭하면 서버를 부르지 않고 바로 남은 거리를 안내한다(안내일 뿐이며 원본 접근은 서버 판정을 통과해야만 가능하다, NFR-08).
- GPS 정확도가 재측정 기준(PRM-03)보다 나쁘면 상단에 얇은 경고 배너를 띄운다. 이때 드롭과 열람은 막히지만 "주변 스캔"은 쓸 수 있다(FR-03, FR-10).
- 주변 목록을 받는 동안에는 FAB 위에 작은 "주변 확인 중" 표시를, 주변에 캡슐이 없으면 "주변에 캡슐이 없어요. 첫 캡슐을 남겨 보세요" 한 줄을 FAB 위에 보여 준다.

## 9. 결정 사항·잔여 리스크

0.1의 미결 사항 Q-01~12를 아래와 같이 결정했다. 판단 기준은 "2일 1인 MVP의 복잡도 최소화"와 "도메인 정의서 규칙을 바꾸지 않고 후속 단계로 미루기"다.

| ID | 쟁점 | 결정 | 근거·잔여 리스크 |
|---|---|---|---|
| Q-01 | 도메인 정의서의 네이티브 전용 기능(IAP BR-07·09, 캡처 차단 BR-21, 기기 식별·무결성 PRV-02, 지오펜싱 푸시 BR-25)을 웹에서 쓸 수 없다 | 이 기능들은 모두 후속 단계로 미루고, Unity/ARCore 네이티브 앱으로 전환한 뒤 도메인 규칙 그대로 적용한다. 웹 PG 결제는 도입하지 않는다 | OQ-10(인앱결제) 결정을 뒤집지 않는다. MVP는 결제·보상이 없어 웹 한계의 영향이 없다 |

| Q-03 | 웹 GPS 오차 때문에 열람 반경(BR-27, PRM-01) 판정이 실패할 수 있다 | 열람 반경은 유지하고 정확도를 보정한다. 이 결정은 도메인 정의서 v0.5에 5.4 판정식으로 반영되었다 (PRM-01, PRM-03, FR-10) | 보정 상한(PRM-03)만큼 열람 반경보다 먼 거리에서도 열람될 수 있다. 실측 데이터로 PRM-03을 다시 정한다 |
| Q-04 | 결제 없이 실버·마스터(영구)를 게시할 수 있다 | MVP는 브론즈만 허용한다 (FR-07) | MVP 데이터가 브론즈 유지 기간(도메인 5.1) 뒤 자동 만료되어 등급 정책(BR-06·08)과 충돌이 남지 않는다 |

| Q-11 | 웹에서는 GPS 스푸핑을 감지할 수 없다 | MVP에서는 수용한다. 보상·결제를 도입하기 전에 도메인 정의서 5.4의 전체 판정(평면 일치, 이동 속도 PRM-05, 무결성 PRV-02)을 필수 조건으로 둔다 | MVP에는 보상·결제가 없어 스푸핑으로 얻을 이익이 없다 |
